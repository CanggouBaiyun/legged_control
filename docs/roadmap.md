#### A. 在线功能

- [ ] **机身高度、roll/pitch。** Python 已有相关静态动作，原生在线节点仍固定高度且 roll/pitch 为零。接入可限幅、平滑、复位的目标，先站立，再验证 trot 中小幅调节及停止时的目标处理。
- [ ] **目标位置与朝向。** 接入目标 x/y/yaw、坐标系和到达保持，处理 yaw 跨界、取消与速度命令接管。与现有速度/姿态命令共用一个 MPC 目标发布者；停止/故障优先。上游参考见 [TargetTrajectoriesPublisher.cpp](https://github.com/qiayuanl/legged_control/blob/master/legged_controllers/src/TargetTrajectoriesPublisher.cpp)。
- [ ] **速度范围与过渡。** 当前在线限幅 vx=±0.10 m/s、vy=±0.05 m/s、yaw_rate=±0.20 rad/s。用户补充原项目演示可达 1.5 m/s，现将平地前向 1.5 m/s 明确列为效果对齐目标（该演示的机器人、配置、持续时间与实测速值尚待核对）。速度阶段围绕此目标集中处理命令限幅/加减速、参考轨迹、步态周期与支撑时间、摆脚可达性、力矩/关节速度和估计时序；通过一个渐变速度场景记录实测持续速度、误差、滑移、姿态、限幅和停止距离，失败则定位原因。当前 0.10 m/s 仅为已验证基线，不是最终速度指标；不逐个速度档开分支。
- [ ] **操控入口统一。** 键盘补齐姿态/目标模式和清楚的状态反馈；话题命令保留。手柄映射作为有相应外设时的扩展，同样复用命令仲裁和停止逻辑。
- [ ] **启动与退出姿态范围。** 现有启动仅覆盖规定的静止准备姿态；补齐约定的初始关节姿态到准备/站立、降低机身和退出的流程，验证过渡和中止。趴卧起身需独立定义可支持姿态，不承诺任意摔倒后自起。
- [ ] **步态配置统一。** 当前仅接受 mode 15/9/6。消除配置文件与 C++ trot 排程重复定义，验收切换时刻、重复请求和停止优先级；其他步态按确切复现目标另行扩展模式与 WBC，不能仅修改 gait.info 即宣称可用。

#### B. 部署控制入口与 SDK2 软件

- [ ] **最小共用控制更新。** 从 `control_simulation.cpp` 提取接收测量、更新估计/MRT/WBC、输出 `JointCommand` 的路径；MuJoCo 真值诊断/推进和实际设备读写留在各自入口。保留已验证的算法和接口，不重写控制器。
- [ ] **完整 LowState 适配。** 复用已有关节映射与 LowCmd/CRC，补 IMU、接触、时间与数据有效性到 `SensorMeasurements` 的转换；安装变换、单位和索引可配置，用合成包核对。真实约定保留为待采样确认。
- [ ] **read/update/write 与离线设备。** 编写接收缓存、固定周期更新和发送/空运行入口；回调不运行 QP 或磁盘写入。用模拟 SDK2 数据源或回放驱动同一控制更新，核对完整输入到 LowCmd 输出。无机器人时不启用实际运动发送。
- [ ] **持续启动与控制权流程。** MPC 编译/等待期间持续接收测量，估计器就绪后使用新鲜状态初始化；控制权申请/释放、首次启用、退出和故障锁定具备可模拟的状态转换。不能将仿真物理暂停的启动流程原样用于机器人。
- [ ] **命令物理约束。** 在共用输出处处理关节位置/速度、增益、命令变化与总力矩（前馈加 PD），复用现有模型限值并记录触发原因；结合机身倾角/高度、策略和估计有效性建立明确退出条件。
- [ ] **看门狗与故障动作。** 区分命令超时正常停步、数据失效、QP 失败及进程失联；设计可模拟的停止/阻尼/禁止继续写入行为和人工重新启用流程。现有仿真清零并冻结不等于机器人停止行为，实际动作必须在接机时验证。

#### C. 数据时序与估计稳健性

- [ ] **正常延迟。** 区分采样、到达、控制时间；处理不同采样频率、重复/乱序帧与时间回绕。建立有限数据年龄内的对齐/预测或保守复用策略，超限故障。禁止通过把旧时间戳改成当前时间来放行；实际时延预算接机再定。
- [ ] **接触错误。** 现有等待/渐变已覆盖短暂误报/漏报；继续处理较长错误、打滑、提前触地和短暂失去支撑，结合观测一致性建立信任/拒收或故障判据。保留计划支撑与测得接触的区别，核对给 MPC 的 mode 语义。
- [ ] **误差范围。** 将现有单配置/单种子扩为有限的偏置、安装误差与噪声范围及组合运动场景，观察长时漂移、速度偏差和协方差有效性；仅在证据需要时增加偏置估计等状态。
- [ ] **估计输出与诊断。** 输出带明确定义坐标系/时间的里程计、关节/接触和估计健康状态，供记录和 ROS 工具观察；控制不得从 MuJoCo 真值回填估计结果。

#### D. 地面、动力学差异与抗扰范围

- [ ] **一般地面接触。** 当前 `floorForces()` 只识别指定 floor 与脚碰撞体；扩到坡面/地形碰撞体，并区分力向量、法向力和用于接触判定的量。
- [ ] **地面与足端参考。** 当前估计器固定地面高度零、球足修正与摩擦约束使用世界 Z 假设；补适用的支撑高度/地面法向、机身相对地面高度和摆脚净空策略，不用真值地形直接冒充感知。
- [ ] **缓坡与低矮不平地面。** 在上述修改后，验证平地进入/离开缓坡、低矮起伏的站立/运动/停步，给出可通过范围。台阶、未知落脚点与感知选脚须按实现能力单独标注，不能由一个坡地场景推断完成。
- [ ] **模型和执行器差异。** 在有限质量/质心、摩擦、力矩限幅、执行延迟/响应变化下验证闭环；参数来自模型或明确的仿真假设，真实辨识留到接机。
- [ ] **抗扰补充。** 复用已通过的八组推扰，补不同 trot 相位、行进中外力、偏离机身质心的作用点/力矩，以及测量误差组合工况。记录恢复时间、滑移、估计误差、限幅和失败边界，避免只有固定相位的一次成功。

#### E. 原项目定位效果与条件扩展

- [ ] **外部里程计接入。** 若复现 T265 定位演示，需补外部 Odometry、传感器外参、世界/里程计坐标、时间对齐、跳变/丢失处理及估计修正；可先用带误差/延迟的模拟里程计验收，再在有设备时验证。上游 [LinearKalmanFilter.cpp](https://github.com/qiayuanl/legged_control/blob/master/legged_estimation/src/LinearKalmanFilter.cpp) 已有跟踪相机里程计入口。普通平地短距离控制不依赖新增摄像头。
- [ ] **手柄/额外步态等扩展。** 有确切使用需求再纳入交付，不把所有机器人演示动作都视为上游已支持能力。自主绕障、感知选脚等需单独界定算法与设备范围。

#### F. 稳定性、复现与学习交付

- [ ] **剩余上游差异核对。** 集中检查 MPC/WBC 参考、名义/反馈输入、质心加速度、接触模式和权重语义，记录有意采用的差异。上游控制器也使用 WeightedWbc；不以更换 QP 求解器或重写为分层 WBC 作为默认前置条件。
- [ ] **历史 QP 故障。** 用保存的失败输入及连续求解上下文核查历史失败，补迭代/残差诊断和有边界的失败处置；离线单帧可解不能视为运行故障已修复。
- [ ] **长时与负载。** 用一次综合场景覆盖反复启动/停步、方向与姿态切换、正反 yaw 跨界、进程/策略失联；检查内存/日志上界与长时漂移。分别记录计算耗时、开始迟到、周期/数据年龄和策略年龄，按实际风险处理超时；目标控制机确定后另验其预算。
- [ ] **可复现构建。** 固定 OCS2 自用分支、SDK2、MuJoCo/Pinocchio/OSQP 等依赖和构建方式，减少个人绝对路径，统一启动配置及默认参数；验证新目录构建与必要的短验收，保留来源和许可证。
- [ ] **最终验收与资料。** 整理功能/速度/地形/扰动/异常的固定场景、门限、报告和演示；README 以当前原生入口为主，旧 Python 保留作基线，旧记录标日期。同步解释数据流、坐标、质心模型、MPC/MRT、WBC/KF 与时间概念，形成简历描述和答辩材料。

按每天 8–9 小时投入，先前离线范围曾粗估为 15–25 个有效工作日；明确 1.5 m/s 对齐目标后，应结合首轮速度范围诊断重新评估高速适配工作量。地形/延迟适配复杂度和失败复现也会影响估计，外部定位与更多步态扩展另据实际范围核算。不含真实机器人调试时间，不能据此保证速度能力或完成日期。

接机后才能确认的项目：真实 IMU/关节/足序与单位、接触字段有效性及阈值、tick 与主机时钟关系、网络时序、真实质量/质心/摩擦/执行器、控制权与停止动作、目标电脑负载，以及实机运动/抗扰效果。离线对应接口可以先准备，真实标定和验收不能勾为已完成。

```text
ROS 2 速度命令 /cmd_vel ──┐

当前 observation ────────┘
ROS 2 步态命令 ────────────→ 现有 mode schedule / GaitReceiver
```

## 原项目结构与采用方式

上游 [`LeggedController.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_controllers/src/LeggedController.cpp) 在同一进程中使用 MPC 独立线程和 `MPC_MRT_Interface`，控制侧直接调用 MRT 和 WBC。[`LeggedHWLoop.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_hw/src/LeggedHWLoop.cpp) 按 read → update → write 执行控制循环。

[`WeightedWbc.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_wbc/src/WeightedWbc.cpp) / [`WbcBase.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_wbc/src/WbcBase.cpp) 提供任务与约束组织参考。上游使用 qpOASES，当前 Python 使用 OSQP；基座加速度任务、摆腿前馈、关节命令增益和变量布局也有差异。直接复用源码时保留来源、版本及许可证。

当前采用 ROS 2 Jazzy。原生控制保留外部 MPC 进程，可选 DDP/SLQ 或 SQP，推荐验收命令明确指定 SQP；策略经 ROS 接收线程更新进程内 MRT，控制线程直接求值和调用 C++ WBC。Python 负责工具、启动前准备和结束后汇总。SQP 接入与任务配置对照已有阶段结果，后续重点转向状态估计和硬件接口。

### 实机最终功能范围

与用户确认的最终目标按实机逐项验收，基础站立/trot 为中间里程碑：

- 从规定准备姿态平滑进入稳定站立，支持机身高度、俯仰、横滚和朝向调整。
- 在线切换站立/trot，完成前后、左右横移、斜向、原地转向和边走边转，支持速度变化及反复启停。
- 到达指定位置/朝向后停住；支持键盘或手柄操控及持续运行。
- 在站立和运动中按量化外力工况验证恢复平衡；逐步验收缓坡和低矮起伏地面，记录适用范围。
- 使用真实 IMU/关节/接触数据和位置/速度估计闭环，接通 SDK2 读写与控制权管理，并验收异常保护、急停、目标平台时序及可复现日志。

当前仿真完成的功能不直接计为实机验收通过。

## 关键数据约定

- WBC：四元数 free-flyer，q=19、v=18，四元数 xyzw；基座速度为局部表达。
- OCS2：24 维质心状态，内部模型使用 Translation + SphericalZYX。它与 WBC q/v 不能直接复制混用。
- OCS2 足序 FL/FR/RL/RR；默认 WBC/SDK 顺序 FR/FL/RR/RL，按名称显式映射。
- ROS 侧 Pinocchio 4.1.0，Conda 侧 3.9.0；各使用明确工具链，通过数值对照衔接。

### 抗扰与估计模块的验收位置

当前量化推扰直接使用传感器启动与估计状态闭环，真值只用于误差统计；实机站立/trot 稳定后再做受控扰动。每次记录作用点、方向、力和持续时间，以及倾角/位置峰值、恢复时间、力矩和时序。估计器沿原项目线性 Kalman 主线：内部估计机身位置 3、线速度 3 和四足位置 12；姿态/角速度由 IMU 提供，关节状态来自电机，实际触地判断作为输入。该滤波器不直接估计三维接触力，SDK2 足底力/接触字段的实际有效性需只读采集核实；MPC/WBC 优化力与实测力分开记录。
