## 原项目结构与采用方式

上游 [`LeggedController.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_controllers/src/LeggedController.cpp) 在同一进程中使用 MPC 独立线程和 `MPC_MRT_Interface`，控制侧直接调用 MRT 和 WBC。[`LeggedHWLoop.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_hw/src/LeggedHWLoop.cpp) 按 read → update → write 执行控制循环。

[`WeightedWbc.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_wbc/src/WeightedWbc.cpp) / [`WbcBase.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_wbc/src/WbcBase.cpp) 提供任务与约束组织参考。上游使用 qpOASES，当前 Python 使用 OSQP；基座加速度任务、摆腿前馈、关节命令增益和变量布局也有差异。直接复用源码时保留来源、版本及许可证。

当前采用 ROS 2 Jazzy。先保留外部 DDP/SLQ MPC 进程，通过策略消息更新控制进程内的 MRT；将逐步管道/服务往返移出控制路径。上游 SQP、任务定义与求解器差异单独比较，便于定位行为变化。

### 2. 本地 MRT 与 C++ 控制循环（已通过 PR #14 合并）

```text
外部 MPC → ROS 接收线程：校验、解码、准备策略缓冲
                         ↓
控制线程：读状态 → 采用有效策略 → 本地 MRT → 参考转换 → WBC → PD/限制 → 写命令
```

已复用 OCS2 的 `MRT_ROS_Interface` / `MRT_BASE` 完成接收线程解码、try-lock 策略选择和控制线程激活/求值。epoch/sequence 与策略一起切换，检查年龄、时间覆盖、有限性和接触模式；同一步当前/未来求值使用同一条策略。reset 只发生在接收线程启动之前。

MuJoCo C API、本地 MRT、参考转换、WBC、PD 与限幅已接通，默认使用 MPC FK 摆腿参考。Python 只负责启动前生成目标和结束后汇总。控制、仿真/诊断/渲染和开始迟到分别记录。运行命令及当前验收结果见[C++ 基线](cpp_model_baseline.md#本地-mrt-与-c-mujoco-闭环2026-10-15)。窗口观察完成后，更新文档、提交推送、合并当前分支，再新建下一阶段分支。

四轮最终 headless 验收（站立、前进停步、左右转）各完成 20 s / 10,000 步。前进最终 90.654 mm，左右转 +9.827° / −9.788°；四轮均无力矩截断。前进完整循环 p99=0.470 ms，去掉前 2 s 后 0/9000 步计算超过 2 ms，但最大开始迟到 1.140 ms，长时间及负载验收仍待完成。

图形入口已接入官方 MuJoCo 3.4.0 Simulate，被动模式保留左右侧栏和鼠标交互，主线程渲染、控制线程同步状态。本地最新 2026-10-16 复跑完成 20 s 前进停步，最终 90.628 mm、无力矩截断；含同步的控制线程循环有 1/9000 步超过 2 ms，不能套用 headless 时序结论。界面截图和 Tab 切换已确认；另补充确认在 4.856 s 提前关闭窗口后，保存 2,428 步数据并正常退出控制线程和配套 MPC。鼠标/Profiler 画面及重置行为仍待人工验收。随后在当前分支提交推送并合并 PR。

### 3. SQP 对齐（当前分支 `feature/ocs2-sqp-alignment`）

当前可用 `legged_robot_sqp_mpc` 已在 OCS2 工作空间构建。现有 `task.info` 的 SQP 配置启用 `useFeedbackPolicy=true`。本分支已扩展本地 MRT 接收校验，允许前馈和线性反馈策略，并按控制器类型检查数据长度；继续使用官方 MRT 解码器。启动脚本已支持 `--mpc-solver ddp|sqp`，默认 DDP，启动时打印所选求解器并检查对应可执行文件。SQP 站立、原地 trot/停步及前进停步均完成 20 s 闭环；本阶段三项验收完成，待提交、推送及合并。SQP 转向和上游 WBC 任务对照仍待完成。

- 前馈策略每个时间点包含 24 个输入值；24 维状态/输入的线性反馈策略包含 24 个偏置和 24×24 个增益，即 600 个值。
- 保留状态/输入维度、有限性、epoch/sequence、接触模式、年龄与覆盖检查，允许官方线性策略解码和求值。
- 启动入口已增加 DDP/SQP 选择并保留 DDP 基线。控制启动时打印实际激活的策略类型；CSV 新增 `policy_controller_type`（1=前馈，2=线性），汇总输出和 JSON 记录各类型样本数。旧 CSV 仍可汇总，但没有策略类型证据。
- 已调整参考转换：当前实测状态通过官方 `evaluatePolicy` 得到反馈输入，用于接触力和关节 PD 速度参考；WBC 运动参考和 5 ms 差分加速度来自同一条已激活策略的规划状态/输入轨迹。接收线程仍只准备缓冲，不在这组求值之间替换已激活策略。该接法避免把固定当前实测状态下的两次反馈求值当作沿规划轨迹的导数；它是当前适配方案，尚非上游 WBC 任务完全一致的实现。

### 5. 实机部署

SDK2 数据采集、关节/IMU/接触映射和时间戳核对可提前准备。部署需要明确控制机、控制权切换、看门狗、限幅、异常停止和急停行为。完成相应仿真验收后，依次进行受保护站立、原地 trot 和低速运动。

## 关键数据约定

- WBC：四元数 free-flyer，q=19、v=18，四元数 xyzw；基座速度为局部表达。
- OCS2：24 维质心状态，内部模型使用 Translation + SphericalZYX。它与 WBC q/v 不能直接复制混用。
- OCS2 足序 FL/FR/RL/RR；默认 WBC/SDK 顺序 FR/FL/RR/RL，按名称显式映射。
- ROS 侧 Pinocchio 4.1.0，Conda 侧 3.9.0；各使用明确工具链，通过数值对照衔接。
