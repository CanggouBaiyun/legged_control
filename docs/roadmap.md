已新增 `hardware/sdk2_readonly` 独立 CMake 采集入口，使用 SDK2 的 `ChannelSubscriber<LowState_>` 接收 `rt/lowstate`。56 列 CSV 记录首帧起的主机单调时间、原始 tick、IMU 四元数/角速度/加速度、motor_state[0..11] 的 q/dq/tau_est，以及 foot_force/foot_force_est 原始数组；保持数组编号，不提前声明四元数、关节或足序映射。DDS 回调只复制字段到有界内存（最多 100,000 帧），结束后保存 CSV，输出按主机到达时间统计的频率及间隔 p99/最大值。这些统计不等同于网络单程延迟或电机控制周期。

首帧等待上限为订阅初始化后 10 s；收到首帧后采集指定时长（默认 20 s，最多 60 s）；流中断超过 1 s 时保存已有数据并报错。Ctrl+C 保存已收数据；拒绝覆盖已有 CSV；缓存满或非有限字段会保留原始采集结果并以错误状态退出。内存缓存期间异常终止/断电尚不能保存数据，这一入口用于短时采样，不用于实机控制或长期日志。采集器只有状态订阅，没有命令发布或控制权切换。

构建：`bash scripts/build_sdk2_readonly.sh`；SDK 前缀默认是相邻的 `unitree_sdk2/install`，可通过 `GO2_SDK2_PREFIX` 指定。`bash scripts/run_sdk2_readonly.sh --help` 已通过；运行脚本选择 SDK2 配套 DDS 库。GCC 13.3 Release 编译通过，使用临时合成 `LowState_` 消息核对原始字段到 56 列 CSV 的对应关系、uint32 tick 边界原样保存及停止后不再追加；这是不经过 DDS 的字段处理检查，不是机器人通信验收。

接机后使用 `bash scripts/run_sdk2_readonly.sh --interface 网卡名 --duration 20 --csv artifacts/go2_lowstate_日期.csv`，首轮记录确认 IMU 约定、重力读数、原始关节/足序、接触字段有效性和数据连续性，再映射到 `SensorMeasurements`。目前尚未连接机器人，没有采集实机结果；网卡、机器人 IP 与连接方式待确认。只读入口的软件准备可单独收尾合并，保留“实机通信未验收”的状态；后续采样与映射结果另行提交，不把软件准备合并当作硬件阶段完成。

#### 机器人暂不连接时的离线推进顺序（2026-10-20）

保持最终实机目标和既有控制核心，按下面顺序推进。首先收尾当前 SDK2 只读准备节点，再新建启动流程分支，避免前一分支未合并就切走。

1. **传感器驱动的启动与控制切换。** 当前 `control_simulation.cpp` 用 MuJoCo q/v 初始化 MPC，并在前约 2.2 s 使用真值控制。实现规定准备姿态下的关节控制、估计器初始化/就绪及 MPC/WBC 切换，仿真从启动起不把真实机身位置/速度送入控制；保留真值只作诊断对照。第一轮目标为已定义的准备姿态稳定启动，更广趴卧姿态的起身范围另行验证。仿真接触标志仍要明确标注来源，实机有效接触输入须接机确认。
2. **复用控制更新和明确异常行为。** 复用现有估计、模型、MRT/WBC 库，整理一次控制更新的传感器输入和关节命令输出（q/dq/Kp/Kd/前馈力矩），在 MuJoCo 执行同样命令组合；离线核对 SDK 索引映射及 LowCmd 字段构造。已有策略年龄/覆盖、状态有效性和力矩限幅检查继续复用，补齐准备、运行、停止和故障状态，以及状态过期、MPC 失联、估计异常或 QP 失败后的行为。仿真的零力矩退出不能直接当作实机停止策略；实际控制权、看门狗和停止动作仍需接机验收。重构范围限于复用上述路径，不另建通用框架。
3. **集中做部署相关的仿真验收。** 加入可控 IMU/关节噪声、偏置、延迟和接触标志抖动，明确假设和可工作的范围；对数据/策略中断做故障注入，检查异常状态确实触发。将持续运动、重复启停和计算超时放入集中验收，保留当前 23/39,000 步控制超时及历史 WBC 失败的未解决记录。当前电脑的结果是基线，目标控制机确定后还需验证其周期与保护行为。
4. **量化抗扰及运动能力范围。** 在估计状态闭环的站立和 trot 中施加已知方向、作用点、力和持续时间，记录位姿峰值、恢复时间、支撑与力矩；速度扩展与组合运动放在同一场景内检查。机身高度/姿态、目标位姿及地形属于最终功能范围，按工况逐步验收，不全部列为只读接机的前置条件。

抗扰可先在 MuJoCo 完成，无需等待实机。当前官方查看器的鼠标扰动已由 `Sync()` 传入 `xfrc_applied`，支持选择机身后 Ctrl+鼠标拖动施力/力矩；这是现有交互通路的代码核对，尚非人工/定量抗扰验收。先用交互观察动作，正式验收增加确定外力参数与恢复统计。主线下一开发项仍为传感器驱动启动，随后集中做含抗扰的仿真验收。操作和边界见[官方查看器记录](cpp_model_baseline.md#官方-simulate-查看器接入)。

下一实际开发项选第 1 项“传感器驱动启动”。上机发送运动命令前，启动及异常处理流程必须具备；只读采样可在用户方便接机时进行。真实关节/IMU/接触映射、实机噪声标定、控制权和目标机最终时序无法只靠离线仿真确认，不把这些记作已完成。

### 在线速度控制：接口核查与下一阶段接入

已读取工作空间当前代码，确定可以复用的链路：

- `ocs2_ros_interfaces/command/TargetTrajectoriesRosPublisher` 发布 `/legged_robot_mpc_target`；SQP 节点已经通过 `RosReferenceManager` 订阅该目标通道，无需重写 MPC 或策略传输。
- `/legged_robot_mpc_observation` 已有当前仿真时间和 24 维状态，可供外部命令节点读取姿态及位置。滚动轨迹的时间使用 observation.time，不用机器墙钟填入 MPC 时间轴。
- `legged_robot_target` 对应 `LeggedRobotPoseCommandNode.cpp`，当前是终端输入相对 XYZ/yaw 的位置目标示例，不能直接当作 `/cmd_vel` 连续速度节点。
- 原项目 [TargetTrajectoriesPublisher.cpp](https://github.com/qiayuanl/legged_control/blob/master/legged_controllers/src/TargetTrajectoriesPublisher.cpp) 有速度转目标轨迹路径：将机身速度转换到世界系，按 MPC 时域生成目标位姿。采用 ROS 2 消息/执行器进行适配，并核对当前质心状态定义和 Go2 关节顺序；不照搬 ROS 1 节点。

拟接入的数据流为：

```text
ROS 2 速度命令 /cmd_vel ──┐
                         ├→ Go2 在线命令节点 → /legged_robot_mpc_target → 现有 MPC
当前 observation ────────┘
ROS 2 步态命令 ────────────→ 现有 mode schedule / GaitReceiver
```

## 原项目结构与采用方式

上游 [`LeggedController.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_controllers/src/LeggedController.cpp) 在同一进程中使用 MPC 独立线程和 `MPC_MRT_Interface`，控制侧直接调用 MRT 和 WBC。[`LeggedHWLoop.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_hw/src/LeggedHWLoop.cpp) 按 read → update → write 执行控制循环。

[`WeightedWbc.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_wbc/src/WeightedWbc.cpp) / [`WbcBase.cpp`](https://github.com/qiayuanl/legged_control/blob/master/legged_wbc/src/WbcBase.cpp) 提供任务与约束组织参考。上游使用 qpOASES，当前 Python 使用 OSQP；基座加速度任务、摆腿前馈、关节命令增益和变量布局也有差异。直接复用源码时保留来源、版本及许可证。

当前采用 ROS 2 Jazzy。原生控制保留外部 MPC 进程，可选 DDP/SLQ 或 SQP，推荐验收命令明确指定 SQP；策略经 ROS 接收线程更新进程内 MRT，控制线程直接求值和调用 C++ WBC。Python 负责工具、启动前准备和结束后汇总。SQP 接入与任务配置对照已有阶段结果，后续重点转向状态估计和硬件接口。

### 实机最终功能范围

与用户确认的最终目标按实机逐项验收，基础站立/trot 为中间里程碑：

- 从规定准备姿态平滑进入稳定站立，支持机身高度、俯仰、横滚和朝向调整。
- 在线切换站立/trot，完成前后、左右横移、斜向、原地转向和边走边转，支持速度变化及反复启停。
- 到达指定位置/朝向后停住；支持键盘或手柄操控及持续运行。
- 在站立和运动中按量化外力工况验证恢复平衡；逐步验收缓坡和低矮起伏地面，记录适用范围。
- 使用真实 IMU/关节/接触数据和位置/速度估计闭环，接通 SDK2 读写与控制权管理，并验收异常保护、急停、目标平台时序及可复现日志。

当前仿真完成的功能不直接计为实机验收通过。

## 关键数据约定

- WBC：四元数 free-flyer，q=19、v=18，四元数 xyzw；基座速度为局部表达。
- OCS2：24 维质心状态，内部模型使用 Translation + SphericalZYX。它与 WBC q/v 不能直接复制混用。
- OCS2 足序 FL/FR/RL/RR；默认 WBC/SDK 顺序 FR/FL/RR/RL，按名称显式映射。
- ROS 侧 Pinocchio 4.1.0，Conda 侧 3.9.0；各使用明确工具链，通过数值对照衔接。

## 工作方式

每组修改交付完整代码、运行命令和验收结果；测试针对具体风险。每个实质阶段完成后更新 README、提交并推送 Git。阶段用时根据已完成的接口、数值对照和闭环结果更新，避免把演示扩展或准备工作当成实机部署完成。

### 抗扰与估计模块的验收位置

在线控制完成后先用仿真真值做基础量化推扰；状态估计接入后，用估计状态反馈重复完整推扰验收；实机站立/trot 稳定后再做受控扰动。每次记录作用点、方向、力和持续时间，以及倾角/位置峰值、恢复时间、力矩和时序。估计器沿原项目线性 Kalman 主线：内部估计机身位置 3、线速度 3 和四足位置 12；姿态/角速度由 IMU 提供，关节状态来自电机，实际触地判断作为输入。该滤波器不直接估计三维接触力，SDK2 足底力/接触字段的实际有效性需只读采集核实；MPC/WBC 优化力与实测力分开记录。
