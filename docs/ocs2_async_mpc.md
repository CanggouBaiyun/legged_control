## 当前状态

C++ MPC 原本已经运行在独立进程；此前仿真端每隔 20 ms 发布观测后，会等待基于该次观测的新策略，导致 WBC 控制循环暂停。本阶段取消运行期间对该次 MPC 求解完成的等待。

## 请求与策略切换

| 请求 | 行为 |
| --- | --- |
| `plan` | 初始化并等待第一条策略；同步模式下继续用于每次更新 |
| `observe` | 发布最新观测和可选步态命令，返回发布确认 |
| `poll` | 处理已就绪回调；检查收到的策略并选择可用的新策略，无更新时保留当前有效策略 |
| `evaluate` | 按当前选定策略的 epoch 与 sequence 查询 C++ MRT |

异步模式第一次 `plan` 后调用 `poll` 确认策略，再建立真实时间起点。随后每 20 ms 调用 `observe` 和 `poll`，控制步长保持 2 ms。每个控制步当前时刻与未来 5 ms 的 MRT 查询使用同一条选定策略；收到策略消息本身不会自动切换 `selected_policy`。

新策略须属于同一 reset epoch，序号向前推进、观测时间不倒退，并覆盖执行区间。`poll` 要求覆盖到下一次更新时刻再加 5 ms；每个控制步还检查当前查询区间及观测年龄。观测年龄上限初设为 100 ms，过期或覆盖不足时停止推进仿真。该阈值是初始仿真配置，后续需结合记录评估。

`observe` 的发布确认不代表 MPC 已收到消息或完成求解。通信管道往返、MRT 服务查询仍为同步调用；服务异常时仍存在超时等待。因此这里的异步指 MPC 策略更新方式，不能据此声称整个控制路径没有阻塞。

## 时间节拍与日志

异步模式按初始化后的固定真实时间起点及仿真时间安排每步启动；提前完成时等待，迟到时保留原时间表并记录迟到量。该方式限制仿真超前于真实时间，不能保证计算过载时仍按时执行。

CSV 新增以下字段：

| 字段 | 含义 |
| --- | --- |
| `policy_reset_epoch` | 当前策略所属初始化编号 |
| `policy_sequence` | 当前选定策略序号 |
| `policy_age_s` | 当前仿真时间减去策略所用观测时间，非独立测量的墙钟通信时延 |
| `policy_updated` | 本控制步是否通过 poll 选择了新策略 |
| `control_start_lateness_s` | 控制循环实际开始时刻相对计划开始时刻的迟到量，可由调度和累计执行超时造成 |

终端每秒打印策略年龄。JSON 保存 `async_mpc`、`policy_updates`、最大策略年龄与最大启动迟到量。同步模式这些年龄和迟到指标在 CSV 中为 NaN、汇总最大值为 null。

`timing_ms.plan` 记录完整策略请求，异步模式通常仅初始化一次；新增 `observe`、`poll` 分项记录通信处理耗时。`loop` 不含步前主动等待，但第一个 loop 样本仍含初始化等待。分析持续运行性能时，应区分该初始化样本。MRT 计时仍为每步两次独立服务往返。

## 第一项通信优化：精简 poll 轨迹载荷

初始化 `plan` 继续返回完整格式，`trajectory_format` 为 `full`。运行期间 `poll` 选中策略后，返回 `height_yaw` 格式，仅包含策略编号、观测时间、原始时间节点、模式时间表和高度/偏航两条诊断轨迹。每个节点的轨迹值由 24 维状态加 24 维输入缩减为高度和偏航两个值；时间与模式信息仍保留，不按比例推断实际耗时改善。

该变化作用于 Python 通信子进程与仿真之间的 JSON 载荷。OCS2 的 ROS 策略发布、C++ MRT 内的完整策略以及每步当前/未来查询均沿用原有控制路径。真实 WBC、关节 PD 和摆腿参考仍使用 MRT 返回的完整状态与输入。

仿真端 `parse_policy_reply` 同时接受完整格式、精简格式和未带格式标记的旧完整格式。完整格式仍先检查 24 维状态/输入，再提取高度与偏航；精简格式直接检查两条轨迹的长度和有限值。两种格式最终提供相同的时间、诊断轨迹和模式数据，供高度预测、0.2 s 展望及终端日志使用。

离线检查已通过：通过实际通信主循环的模拟回调确认 plan 返回完整载荷、poll 返回精简载荷，随后 MRT 查询仍按正确策略编号返回全部 24 维状态和输入。将该检查实际生成的两种 JSON 载荷交给仿真解析，诊断数组和重复时间节点附近的插值结果完全一致；旧格式兼容，异常长度、非有限值、逆序时间、未知格式及非法模式会被拒绝。此检查不运行真实 MPC 闭环，不能替代下述动作和时序验证。
