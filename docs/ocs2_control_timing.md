# 控制循环逐步耗时分析

## 状态与目标

2026-10-15，在 `feature/ocs2-control-timing` 为 OCS2–WBC–MuJoCo 实验接入每步分段计时及独立 CSV，完成首次 20 s 异步前进和停步后，又接入 MRT 内部计时并完成同任务 20 s 验证。此次增加测量，不改变 MPC/WBC 参数、步态、目标轨迹或策略选择规则。最新运行排除前 2 s 后，9000 步中有 2008 步超过 2 ms；C++ 两次求值平均合计约 4.52 μs，新策略激活步骤的激活耗时平均 0.539 ms，ROS 往返扣除 C++ 回调后的剩余耗时最大 7.056 ms。下面分别保留两轮结果，作为本地 C++ MRT 接入的对照基线。

此前 4 ms 策略检查下，前进及左右转的循环平均耗时约 1.70–1.74 ms，p95 约 2.5 ms，仍有控制步超过 2 ms。逐步记录用于将某一次超时与当步各阶段耗时对应，决定下一项通信或 C++ 控制循环改动，不能只用全程平均值判断固定 500 Hz 是否满足。

## 分段口径

每步从主动节拍等待结束后的 `loop_start` 开始，以连续时间点划分以下互不重叠的阶段，单位均为 ms：

| 字段 | 范围 |
| --- | --- |
| `state_ms` | MuJoCo 状态映射、当前目标计算与状态检查 |
| `policy_ms` | 到期的 plan/observe/poll、策略年龄及覆盖检查、当前质心状态转换和查询准备 |
| `mrt_pair_ms` | 一次双时刻 MRT 请求，含 Python 管道、ROS 服务往返和响应解析 |
| `reference_ms` | mode 核对、控制器选择、足端运动学、当前/未来 WBC 参考及加速度前馈 |
| `wbc_ms` | WBC 求解和求解结果/约束残差检查 |
| `command_ms` | 关节参考转换、现有 PD 参考差异诊断、关节 PD、力矩映射、限幅及写入 MuJoCo 控制量 |
| `logging_ms` | 主运动记录组装、力顺序转换、终端每秒打印及其 lookahead 诊断 |
| `simulation_ms` | `mujoco.mj_step` |
| `contact_ms` | 地面接触力/速度诊断、接触历史更新及本步运动记录补全和入队 |
| `viewer_ms` | 条件分支及可选窗口同步；无窗口时通常接近零 |
| `timing_record_ms` | 最后阶段结束后到循环计时结束之间，分段耗时及计时行的组装、入队 |
| `loop_ms` | 从 `loop_start` 到本步计时行入队后的总耗时，含上述各段 |

时间来源为 `time.perf_counter()` 的墙钟时间，包括等待和被调度暂停的时间，不等同于 CPU 计算时间。各标记的少量记录成本也会落在相邻阶段；`timing_record_ms` 不代表全部测量成本。最终回填总耗时及下一步准备等少量操作发生在最后计时点之后。

现有 `timing_ms.wbc` 只包住求解调用，新 `wbc_ms` 还包含结果检查。旧 `timing_ms.plan/observe/poll` 是 `policy_ms` 的子项，不能将两组数直接相加。单步分段与 `timing_record_ms` 之和应等于 `loop_ms`；程序检查有限性、非负性及求和误差（容差 1e-6 ms）。各段 p95/p99 的和不等于整步 p95/p99。

## 数据对应与初始化

主运动 CSV 保留原来的 103 列。初版计时 CSV 包含 22 列：step、积分前的 time_s、mode、初始化标记、plan/observe/poll 调用标记、策略更新标记、策略年龄/启动迟到量，以及 12 个耗时字段。当前版本增加 14 个 MRT 内部计时及计数字段，共 36 列，新增字段插入在 `loop_ms` 和 `timing_record_ms` 前；按字段名读取，不依赖尾部固定偏移。程序检查计时记录与运动记录的样本数、time_s 和 mode 一一对应。

MuJoCo 推进之后使用本步运动行保存的 time_s，避免计时行被错误标记到下一步。策略年龄及启动迟到量在计时 CSV 中使用 ms，主 CSV 中仍为 s；同步模式对应值为 NaN。

所有样本都写入计时 CSV，首次初始化所在行的 `initialization_step=1`。新增 `control_timing` 汇总沿用运动评估区间：通常排除前 2 s，短于该区间的实验使用全部样本。完整 20 s、2 ms 步长的正常运行预计有 10000 行计时数据，其中 t ≥ 2 s 的汇总样本为 9000。原有整轮计时和超时计数仍包含初始化，因此可能与新增汇总不同。

已通过语法编译、`git diff --check` 以及定向离线检查：初始化排除、超时统计、无超时情况、分段求和不一致和负数/非有限耗时的拒绝。随后完成下述真实 ROS/MuJoCo 20 s 集成运行，未重复完整 pytest。新计时会增加开销并可能影响异步调度，不能将前后两次运行的全部耗时或动作差异归因于计时语句。

## MRT 查询内部计时与闭环验证

### 计时字段与范围

`EvaluatePolicyPair` 的成功响应新增策略激活标记和四项 C++ 回调内计时。服务端使用 `std::chrono::steady_clock`；两个 Python 进程分别用 `time.perf_counter()` 记录各自的耗时。进程间传递耗时值，不直接相减不同进程的时间戳。

| 计时 CSV 字段 | 范围 |
| --- | --- |
| `mrt_pipe_roundtrip_ms` | 仿真端发出管道请求，到读到 JSON 回复并完成解析；请求字典构造和后续参考转换在此段之外 |
| `mrt_transport_query_ms` | ROS 传输进程的 `query_mrt_pair` 内部，含校验、服务可用性检查、所有请求尝试和参考/计时字段组装 |
| `mrt_ros_ready_ms` | `wait_for_service` 可用性检查/等待 |
| `mrt_ros_roundtrip_ms` | 所有 `call_async` 到 future 完成并取得结果的时间之和，含序列化、DDS/执行器等待、回调和响应处理 |
| `mrt_ros_success_roundtrip_ms` | 最后一次成功请求的同一往返区间 |
| `mrt_cache_retry_wait_ms` | 策略暂未缓存时，重试之间 `spin_once` 的耗时之和 |
| `mrt_ros_attempts` | 本步服务请求尝试次数，成功无重试时为 1 |
| `mrt_cpp_policy_activated` | 成功请求是否激活了另一条指定策略，0/1 |
| `mrt_cpp_activation_ms` | 成功请求中策略解码、缓冲及激活的耗时；复用时为 0 |
| `mrt_cpp_current_eval_ms` | 当前时刻求值及输出有效性检查 |
| `mrt_cpp_future_eval_ms` | 未来时刻求值及输出有效性检查 |
| `mrt_cpp_callback_ms` | 成功请求 C++ 回调总耗时，含请求校验、策略查找、激活、两次求值和参考数组填写；不含回调前的排队或返回后的响应序列化 |
| `mrt_pipe_residual_ms` | 管道往返减去传输查询内部耗时；含管道/JSON、调度、函数外分派及回复处理等剩余开销 |
| `mrt_ros_residual_ms` | 最后成功的 ROS 往返减去 C++ 回调耗时；含 DDS、序列化、执行器排队、传输进程其他回调和调度等剩余开销 |

这些是嵌套的子项，不能与原分段相加，也不能把所有 `_ms` 列求和；原互不重叠的分段求和检查只使用 `CONTROL_TIMING_PHASES` 及 `timing_record_ms`。ROS 剩余时间使用最后成功往返，避免把失败重试总时间与一次成功回调错误对应。重试步骤的 C++ 计时仅代表最后成功的回调，不累计失败回调。

两个剩余值是耗时之差的估计，不是独立测得的纯网络或管道时间；不做截零处理，保留可能出现的微小测量误差。内层参考检查、策略编号和预测区间校验保持原规则。服务类型改变后，旧类型节点不应混用；缺失计时字段会报错，不会用零值伪装为已测量。

`evaluate_policy_pair` 继续返回原六项参考，主循环通过可选字典参数取得计时。JSON 在 `control_timing.mrt_query` 增加各项 mean/p95/p99/maximum、新策略激活次数、重试步骤数、请求总次数、仅激活步骤的激活耗时统计及超时步骤的子项平均耗时。评估区间仍通常为 t ≥ 2 s，计时数据通过同一行的 step/time_s/mode 与原分段对应。

ROS 剩余耗时超过 1 ms 的 903 步全部属于策略复用步骤，也全部整步超时。最慢整步在 **t=15.392 s、mode=9**：整步 8.608 ms，MRT 整段 7.254 ms，ROS 往返 7.062 ms，而 C++ 回调仅 **0.00635 ms**；当步未激活策略、未重试。这把该次长尾定位到 C++ 回调区间之外，具体可能包含 DDS、序列化、执行器排队、Python 其他回调及进程调度，现有计时无法进一步确定各自占比。不能将 7.056 ms 剩余值直接称为网络延迟或某一种回调的耗时。

#### 动作与策略时效

首次双足模式在 4.042 s，持续四足站立从 16.020 s 开始。最终 x 为 0.090636 m，相对 0.09 m 目标误差 +0.636 mm；8–12 s 目标位置 RMSE 为 12.247 mm，最大落后 17.646 mm。四脚支撑实际触地比例均为 100%，摆动中段触地样本均为 0；最大电机力矩 16.708 N·m，未限幅。动力学/接触加速度残差最大约 1.95e-6/4.02e-7；OSQP 仍为 4 次 setup、9996 次 update。

策略年龄中位数/p95/最大值保持 22/32/38 ms。动作及约束结果与已有基线接近，异步调度下不要求每步轨迹或接触切换时刻完全一致。该运行验证了内部计时与闭环共存，尚未达到稳定 500 Hz。

### 下一阶段：本地 C++ MRT 原型
