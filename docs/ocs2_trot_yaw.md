# OCS2 原地 trot 偏航转向验证记录

## 目标与实现

`--turn` 在 8–9 s 平滑增加偏航角速度，9–11 s 匀速，11–12 s 平滑减速；12 s 后保持相对初始朝向的目标角度。`--turn-angle-deg` 默认 10°，正值左转、负值右转；已验证的命令为 ±10°，对应峰值角速度幅值 3.33°/s，其他角度尚未验证。完整目标时间表包含旋转后的基座姿态、名义足端布局和对应质心动量。MPC 与摆腿规划使用同一带角度参数的目标函数。

摆腿落点在起摆时锁定。水平落点按摆动中点的目标偏航角速度乘以 0.70 s 步态周期，绕实测基座位置旋转足端相对位置。支撑脚仍由 WBC 接触约束处理。这是简化落脚规则：尚未根据实际偏航角误差修正落点，目标角速度归零后，转向落点增量也归零。

## 运行

先启动 MPC 和 MRT 服务，见 [原地 trot 记录](ocs2_trot.md)。三个终端均使用 `ROS_DOMAIN_ID=214`：

```bash
env -u PYTHONPATH ROS_DOMAIN_ID=214 \
  /home/bot/miniconda3/envs/go2_control/bin/python \
  examples/mujoco/ocs2_wbc_standing.py \
  --headless --duration 20 --allow-trot --trot-at 3 --stop-trot-at 15 --turn \
  --csv artifacts/ocs2_wbc_trot_yaw.csv
```

本次图形窗口因 GLX 上下文创建失败而不可用；同机 `nvidia-smi` 报 NVIDIA 驱动与 NVML 库版本不一致。以下结论来自无窗口仿真数据，没有窗口动作复核。

完成 20 s、10,000 个仿真步，无 WBC 失败中止，力矩限幅为 0 步。**首次偏航目标跟踪未达标，不能记为完成 10° 转向。** CSV 的 `goal_yaw_rad`、`mpc_yaw_rad` 和 `measured_yaw_rad` 分别记录外部目标、当前 MRT 策略参考和 MuJoCo 实测角度。

| --- | ---: | ---: | ---: |
| 9 s | 1.667° | 0.039° | 0.039° |
| 10 s | 5.000° | 0.276° | 0.276° |

8–12 s 实测相对目标的偏航 RMSE 为 5.44°，最大误差 8.57°；16.1–20 s 的目标跟踪 RMSE 为 5.82°。当前 MRT 参考与实测角度很接近，但每 20 ms 根据实测状态重新规划会使策略起点接近当前状态，这不能单独证明完整策略或 WBC 的转向跟踪正确。

15 s 发送停步指令，最后双足支撑样本在 15.998 s，从 16.000 s 起持续四脚支撑。最终基座位置为 [0.000975, -0.003149, 0.282975] m。最大电机力矩 22.52 Nm，最大足端地面法向力 103.17 N。计划支撑时地面法向力大于 1 N 的比例为 FR 99.984%，其余三脚 100%；摆动中段实际触地样本为零。四脚摆动高度 RMSE 为 5.78–6.60 mm；连续实际支撑时足端中心水平速度 p95 为 2.97–4.26 mm/s，不能直接解释为触地点滑移速度。

WBC 平均耗时 0.802 ms，完整循环平均 3.398 ms；1731/10000 步超过 2 ms。MPC 更新仍同步阻塞仿真循环，首次请求包含初始化耗时 619.81 ms。当前结果尚不代表实机实时执行能力。本轮未重新运行自动回归测试。

数据为本地 `artifacts/ocs2_wbc_trot_yaw.csv` 和同名 JSON，原始数据不随 Git 提交。上表偏航指标由 CSV 分析得到，现有 JSON 摘要未包含偏航误差。

## 未来偏航计划诊断

同配置第二次 20 s 运行增加了未来 0.2 s 偏航计划、规划窗口末尾偏航角和未来 0.2 s 平均计划转速的终端输出。数据见本地 `artifacts/ocs2_wbc_trot_yaw_diagnostics.csv` 和同名 JSON。

12 s 时实际偏航为 1.598°；当时的 MPC 计划在 12.2 s 达到 7.82°、窗口末尾达到 9.78°，但 12.2 s 实际只有 1.691°。第二次运行最后记录实际为 4.260°，仍明显落后于 10° 目标。未来计划表明 MPC 已产生较快的转向规划；不能将缓慢转向直接归因于偏航状态权重不足。

代码检查发现 WBC 基座任务有线加速度前馈，角加速度任务只有姿态与角速度误差反馈，没有接入 MPC 角加速度前馈。每次重新规划时初始参考与实测状态接近，角速度反馈也可能无法立即产生计划所需的角加速度。下一步应补齐该通路并做同配置对照，再判断剩余执行误差、加速度限幅和落脚规则的影响；目前尚未验证缺失前馈是否为唯一原因。

第二次运行仍完成 10,000 步、力矩限幅 0 步，16 s 起持续模式 15；最大电机力矩 22.53 Nm，3217 步超过 2 ms。此次仅增加诊断输出，不能把超时步数变化解读为控制性能改善或退化。

## 接入角加速度前馈后的对照

仿真复用已有未来 5 ms 的 MRT 查询，对同一策略的当前与未来角速度作差分。两次角速度都表达在同一个当前实测机身坐标系中，所得角加速度传入 WBC 基座任务，与姿态和角速度误差反馈相加，再经过原有 ±5 rad/s² 分量限制。该通路覆盖三个角加速度分量，并非只作用于偏航。未传入前馈的调用默认使用零前馈。

第三次同配置运行完成 20 s、10,000 步，数据见本地 `artifacts/ocs2_wbc_trot_yaw_angular_ff.csv` 和同名 JSON。

目标 12 s 达到 10°，实测从 13.192 s 起进入距目标 1° 的范围；15 s 发停步指令，16 s 起持续四脚支撑。最终基座位置为 [0.000670, 0.000494, 0.280806] m。结果支持原地小角度转向并停步的初步闭环验证，但转向过程仍有滞后，不能视为精确跟踪完整时间轨迹。

支撑触地比例仍为 FR 99.984%、其余三脚 100%，摆动中段实际触地样本为零；摆动高度跟踪 RMSE 为 5.75–6.61 mm。最大地面法向力为 103.94 N，足端中心水平速度 p95 为 3.18–5.17 mm/s。该代理量未证明接触点无滑移，四脚 y 方向的目标和实际摆动也尚未记录。

最大动力学残差为 1.78e-5，最大接触加速度残差为 6.86e-6；完整循环平均耗时 3.394 ms，3121/10000 步超过 2 ms。同步 MPC 更新和图形环境限制仍然存在。角加速度前馈明显改善了转向，但剩余滞后、角加速度限制和落脚规则的影响仍待分别分析。

接入角加速度前馈后，用户运行现有完整回归测试，结果为 **38 passed、6 warnings，14.08 s**。现有测试通过支持公共任务接口与已有动作的兼容性；本轮 20 s 转向运行另行提供集成验证，现有自动化测试尚未专门覆盖偏航角命令跟踪和二维转向落点。
